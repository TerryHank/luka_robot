# 露卡：人体与身份识别，第一阶段

本目录提供本地静态识别与显式人脸登记。它没有 ROS 运动发布、导航目标或轮速接口，**尚不能让小车跟随行走**。

## 使用

打开 [监控页](http://192.168.3.251:8503/?version=people-monitor#nxPeople)，进入“人体与身份识别”。

1. 点“启动静态识别”。会复用现有 RGB-D 相机流，不再打开第二路 USB 相机。
2. 在实时画面或人体列表中选中要观察的人。
3. 登记本人时填写称呼，点“为选中目标登记人脸”。保持位置稳定，正对镜头并轻微变换角度。
4. 最少采集 3 份不同的清晰人脸样本后，可点“完成录入”；采满 8 份会自动保存。满 3 份且经过 15 秒，也会在当前帧仍有清晰正脸时自动保存。
5. 离开画面再回来，核对是否显示所登记的称呼。此项必须进行真人正样本及其他人负样本验证，不能用单元测试代替。
6. “停止识别”会退出独立识别进程，释放模型内存。已登记资料保留，可以单独删除。

当前相机仍是离地约 20 cm、朝正前方。正常站立可能只拍到腿；登记时需让完整正脸入镜。人脸短边至少 64 像素，侧脸、倾斜、模糊、多人脸、边缘裁剪会拒绝登记。质量不合格时不能通过降低身份匹配阈值补救。

上半身截断、RGB/深度不同步、深度分层或深度过于分散时显示“距离未知”，不用地板、椅子或两腿之间的背景代替人体距离。

## 实现与边界

- 人体：默认使用 NVIDIA PeopleNet TensorRT FP16，仅使用 person 类；启动失败会自动回退现有 YOLO11n COCO TensorRT FP16。可通过 `NX_PERSON_DETECTOR=yolo` 明确切回 YOLO；现有家庭物品识别词表和模型保持独立。
- 轨迹：图像重叠、位置、深度和双置信度续接，仅用于静态观察。不是 BoT-SORT，也不是跨摄像头或长期身份跟踪。
- 人脸：OpenCV YuNet 检测与 SFace 特征，CPU 推理；姓名来源只限用户主动录入的本机资料。
- 身份：余弦相似度至少 0.50，与第二候选差至少 0.08，连续 3 次一致才显示姓名。分数不是身份概率；上述阈值仍需现场验证。
- 存储：SQLite，每人最多 8 份 128 维特征，最多 32 人。当前组件不存储人脸照片、录像或音频，不上传特征。
- 失效：漏检且没有其他候选人时最多等待 0.6 秒；唯一已选轨迹只有难以区分的弱候选时，也可在原观察时间起等待最多 0.6 秒，且必须由清晰、无歧义的强检测恢复。等待不输出旧人体框、距离或当前身份。多人关联有歧义、等待超时或相机数据超过 0.7 秒时清除锁定；不可见即取消未保存的录入。
- 资源：人体循环上限 8 FPS，每轮最多分析 2 张脸、同一人体的人脸计算至少间隔 0.18 秒；启动前检查视觉任务冲突及内存余量。系统内存使用超过 7.3 GiB 后退出模型进程。
- 开机：只启动轻量管理服务，人体/人脸模型按需加载。当前不接语音“跟着我”。
- 人员关联：用户明确确认后，可把人脸 UUID 与已登记声纹 UUID 一对一关联。有效关联沿用声纹 UUID 作为 `person_id`，现有声纹聊天记忆无需迁移。不会根据同名自动关联，也不会用画面里的脸替代不确定的说话人。

“无脸”不等于“陌生人”，轨迹编号也不等于身份。第一次登记后仍需测试遮挡、转身、出入画面及多人交错；不能凭一次识别结果自动选择跟随对象。

## 远处选择与本次目标保持

监控页增加“本次目标确认”：点击人体框，选择已登记人员，再点“确认身份并锁定”。这会把用户明确指定的人员关联到本次连续人体轨迹，不要求再次靠近拍脸，不新增或修改人脸样本，也不建立新的声纹关联。

自动人脸识别连续确认身份后，同一已选人体即使转身，也可保留本次目标的称呼。`target_session` 与当前帧 `tracks[].identity` 独立：前者明确标注来源为 `face_match` 或 `user_selection`，后者在看不到脸时仍为身份未核对。手动指定或保留的目标信息不用于声音归属、个人聊天记忆或身份认证。

该保持只适用于连续轨迹及最多0.6秒、没有竞争目标的短暂漏检；超时、画面过期、多人关联歧义、明确身份冲突或档案删除均撤销，需要重新点选。不会按同名或衣服在目标走失后自动接管另一个人。当前仍是静态验证，没有轮速、跟随导航或语音启动跟随。

### 转身掉锁修复（2026-09-21）

实测发现，上半身框与全身框的 IoU 约0.356，同时低于检测NMS的0.45、超过跟踪歧义门槛0.35，导致同一个人被当成两个候选反复换号。新清理步骤核对包含率、顶部位置、水平中心、深度及脸数量后才合并嵌套框；缺少有效深度时还必须检测到恰好一张脸。两个不同深度或多张脸不合并。

新目标仍要求置信度0.45；0.18–0.45的框只能严格续接既有轨迹，不可新建、选择目标或采集人脸。较低质量续接距离最后可靠人体观察最长1.2秒；连续、唯一且几何一致的0.30–0.45新观察可以更新人体连续性时间，不能更新人脸身份时间。短暂漏检期间显示 `waiting_detection`，保持历史目标信息但 `visible=false`，禁止身份确认与登记，超过0.6秒或出现竞争目标即撤销。

匹配真正分为两个阶段：先仅用强检测做关联和歧义判断，冻结已匹配轨迹；弱检测只能续接剩余轨迹，不能注销强匹配。仅把强框排到前面、仍对所有弱框一起判断歧义，会继续触发误解锁，这种早期实现已被替换。

唯一已选旧轨迹遇到多个代价相近的弱候选时，不挑选其中一个，而是暂时不输出人体。等待锚点固定为最后一次有效观察，后续弱框和页面轮询都不能延长期限，只有原位置/深度门限内的无歧义强框能恢复原编号。多人历史轨迹或强框之间的冲突仍取消锁定。人体列表按编号复用按钮，置信度和距离刷新只更新文字，避免点击时节点被移除。

跟踪、当前人脸、JPEG及目标会话在同一锁内提交，防止页面轮询在新旧帧之间读到“空目标”而错误解除锁定。没有增加模型，没有改人脸匹配阈值或相机分辨率。

一段约9秒的60帧实时检测数据回放：旧逻辑14帧没有目标，第5帧解除选择；新逻辑14次弱检测续接，60帧保持同一编号及选择。它验证的是该段数据的连续性，不等于多人交错或实际行走跟随已经验收。对应数据与结果在本机 `work/person_follow/tracking_{trace,replay_results}.json`，不包含图像、声纹或人脸特征。

另一段约9秒的60帧数据有32帧只有弱检测。相较于早期的全候选歧义判断，两阶段版本产生的编号由20个降至2个；选中后的58帧中，42帧保持选择，其中5帧为不可见等待。一次等待成功恢复，另一次持续超过0.6秒仍取消。这说明重复框导致的跳号已明显减少，但持续遮挡或长时间弱检测仍会丢锁，不能把这两段回放当成连续行走跟随的验收。

随后真人反馈仍会换号。新的160帧、约20秒事件记录表明：人体始终位于相近位置，转身/遮挡后分数约0.34–0.43，但程序在距最后强检测1.2秒后拒绝所有弱框，再等0.6秒注销轨迹，重复发生4次；相机并未过期。

为此将 `last_reliable_body_seen` 与 `last_strong_seen` 分开。只有唯一旧轨迹、唯一当前候选、相邻处理帧都有真实观察且间隔不超过0.3秒，才能累计中等分连续性证据；要求IoU至少0.4，框顶部横移不超过较小框宽的15%、纵移不超过较小框高的10%，宽比0.65–1.55、高比0.45–2.2，两次有效深度差不超过0.25米。累计至少3次连续证据才更新可靠人体时间。框、分数、深度均使用当前检测，深度未知仍保持未知；强检测时间和弱框的人脸限制不变。缺帧、低于0.30、多候选或等待强检测期间，不能用此规则续期。

该160帧事件回放从4个编号、40帧空输出，改善为同一编号、无空输出，160帧保持选择。前述较难60帧仍有一次因弱候选歧义等待超过0.6秒而取消，没有放大等待时间。静坐实机曾通过16秒/100次、39秒/500次状态采样，但用户走动反馈仍失败，因此这些静坐记录仅作为资源与静态稳定性记录，不能代表运动验收。回放资料在 `work/person_follow/body_continuity_replay_results.json`。

自动诊断最多缓存160帧/20秒的框、分数、深度和关联状态。换号/退休时写 `data/tracking_event.json`；选中目标清除时另存 `data/tracking_selected_loss.json`，避免被后续未选中换号覆盖。文件权限0600，不保存图像、人脸特征、姓名、身份UUID或声纹数据；写盘失败不影响追踪。

本机只读测得 RGB 内参 `fx=fy≈541.965`，画面 640×480。在相机离地20cm、水平朝前的假设下，2m处画面上沿约为离地1.10m；脸中心高1.5m时约2.9m才刚进入上沿，而16cm宽的人脸此时只有约30px。此估算解释了低机位与64px识别门槛的冲突，不是实测最远识别距离。原生高清模式可增加像素，但不能改善当前近距离头部不入画的问题；本次未更改相机分辨率或 RGB-D 标定。

## 实机记录：2026-09-21

### 短时遮挡后恢复所选目标（新增）

采用 OSNet x0.25 的 CPU 外观特征辅助关联，目标为 8GB 预算。当前仅为静态识别和锁定，仍不发车轮指令。两个相邻清晰强观测建立临时外观模板后，选中目标真正漏检时保留最多 3 秒核对窗口；没有模板时仍按原 0.6 秒策略处理。等待期间不显示旧框、旧距离或当前人脸识别结论。

恢复原编号需要外观相似度、候选间差距、框位置/尺寸、可用深度和两帧连续验证同时通过；明显外观不符、多人竞争、已有其他轨迹归属、相机过期、超时、解锁都不自动恢复。连续强框重叠歧义仍维持保守清除策略。外观特征仅在内存中保存，最多每轨迹 4 份、10 秒时效；不写身份库、不代表重新确认人脸或声纹身份。

NX 单独测得 OpenCV DNN CPU 两线程，单人体框 30 次有效样本的平均耗时 16.98 ms、P95 19.29 ms；模型加载前后进程 RSS 约从 47.78 MiB 到 60.71 MiB。导出 ONNX 为 891,011 字节，NX 输出与开发机参考输出最大绝对差约 5.39e-5。上述增量不等同于完整人体识别服务的总内存；完整流程及真实遮挡成功率仍需现场验证。

模型及预处理来源为 [OSNet 作者仓库](https://github.com/KaiyangZhou/deep-person-reid) 的 MSMT17 combineall x0.25 权重。导出仅在开发电脑使用 PyTorch，NX 只增加 ONNX 和现有 OpenCV CPU 推理。作者代码 MIT 许可随模型保存；权重和训练数据的商业使用权限需另行核查，不将代码许可作为商业权重授权证明。`appearance_reid.selected_recovery_ready` 可查看当前所选人体是否已有可用模板。

## 人脸与声纹的对应关系

关联保存在人脸库 `face_voice_links` 表，不复制声纹特征，不复制聊天历史。`IdentityStore.bind_voice_profile(face_profile_id, voice_profile_id)` 仅由本机维护调用；当前没有开放浏览器绑定接口。重复确认同一对应关系是幂等操作，已有冲突关联会拒绝覆盖。

每次读取关联时，仅以只读方式检查声纹 UUID 是否仍为已登记状态。删除声纹后关联显示不可用；以同名重新录入会获得新 UUID，需再次明确关联。数据库暂不可读时不输出有效 `person_id`。删除人脸会同时移除它的关联记录。

人脸状态为 `matched` 且画面新鲜时，实时状态才附带有效 `person_id` 和 `voice_profile_id`。未见人脸、识别未确认或画面过期时不沿用上一次的人员编号。

现有语音链路继续用当前这段音频的声纹结果选择记忆；关联元数据不赋予控制权限，也不说明画面里的“主人”就是此刻说话的人。
