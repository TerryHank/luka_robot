# NX 小车使用说明与指令表

更新：2026-09-10。适用于 192.168.3.251 上当前部署版本。

## 一键启动（2026-09-11 新增）

打开 http://192.168.3.251:8503/ ，点击“一键启动小车功能”。按钮补齐雷达、定位、底盘、手柄、导航、语言代理、露卡语音、聊天模型服务、相机及物体记忆服务。已运行的服务不会重启，不会自动行驶或开始录像。

页面逐项显示服务状态。“运行中”表示服务进程已启动，首次语音加载仍需约 35 秒。聊天和视觉模型继续按需加载。重启后先检查地图位置和朝向再导航；启动成功不代表定位及导航效果已验证。

网页服务已设置开机启动。网页无法打开时，可 SSH 登录执行 `sudo systemctl start nx-dashboard`。命令行一键启动为 `sudo /usr/local/sbin/nx-start-functions`。

## 1. 最常用的入口

### 一键重启功能与雷达恢复（2026-09-11）

8503 页面新增“一键重启功能”：先停止导航、手柄和底盘输出，请求结束录像，再重启传感器、定位、语音、聊天和相机服务，最后启动底盘、手柄、导航。这是功能服务重启，不是 NX 整机重启；旧导航目标不会自动恢复。定位服务重启后需检查并恢复定位，重新选择目标。语音首次加载约需 35 秒。

高位雷达开机缺失的问题源于网卡地址未就绪时转发进程绑定失败，驱动随后超时且没有自动重试。现已加入地址等待、代理与驱动进程自动拉起，以及连续三次扫描读取失败后重新连接。雷达硬件断电或线路未恢复时仍需恢复硬件连接；判断恢复成功应看“运行健康检查”里的实际数据时间，而不只是服务进程状态。

手机或电脑连接小车所在局域网，在浏览器地址栏输入：

| 功能 | 地址 |
|---|---|
| 小车地图、航点导航、文字命令、手动唤醒 | http://192.168.3.251:8503/ |
| 本说明 | http://192.168.3.251:8503/help |
| 相机、LocateAnything 识别、录像查找 | http://192.168.3.251:8091/view |
| Qwen 本地聊天 | http://192.168.3.251:8092/ |

当前实际开放：实体手柄遥控、四楼航点导航、相机识别、录像搜索、文字聊天、语音聊天。

**语音现已开放固定短句“去厨房”“去卧室”“去浴室”和“停止导航／停车／停止”，直接调用真实四楼导航接口。先唤醒露卡，等“在呢”后说完整短句。网页文字框与其他任务命令仍只解析。语音需要唤醒且有识别延迟，紧急停车仍用手柄 LB 或网页“停止导航”。**

语音导航新增于本次更新：路由、否定句拦截、接口超时不重试和模拟背景声断句已通过测试；真实语音发起并到达目标的闭环尚待实车验证。导航到达状态查看网页。

巡航任务调度、跨楼层电梯、跟随、自动充电还未开放。视觉页面里的“巡航录像”是录像功能，不会自动让小车巡航。当前录像搜索返回时间与候选框，尚不能直接给出物体的准确地图坐标。

## 2. 露卡语音与手动启动

正常使用：喊“露卡”→等待“在呢”→说“你好”或一句问题→停顿约 0.6–1 秒，等待回答。每次新对话重新唤醒；播报期间避免同时讲话。唤醒后说话窗口约 10 秒。

如果喊名字没反应：点击小车网页顶部的“手动唤醒露卡”，等“在呢”后说话。按钮只请求开始聆听，服务未启动时会提示错误。

首次启动需加载语音模型并预热，实测约 31 秒。看到日志 `ready wake_word=露卡` 和 `audio_capture_started` 才表示准备完成。

电脑打开 PowerShell，先连接 NX（以下服务命令均在 SSH 登录后执行）：

```bash
ssh nvidia@192.168.3.251
```

这台电脑已配置免密 SSH。其他电脑需要另行配置密钥。sudo 如要求密码，输入 NX 的登录密码，输入时不显示字符。

```bash
nx-voice start          # 启动语音和语言代理，等待约 35 秒
nx-voice wake           # 手动唤醒一次，等“在呢”后说话
nx-voice cancel-listen  # 取消这次聆听；不用于停止小车或中断已提交任务
nx-voice status        # 查看语音和语言代理状态
nx-voice logs          # 实时语音日志；Ctrl+C 只退出日志查看
nx-voice restart       # 重启语音服务，重新等待模型准备
nx-voice stop          # 关闭麦克风唤醒服务，语言代理仍运行
```

本次已启动语音服务；目前语音没有设置开机自动启动。如希望以后每次开机自动启动，可执行：

```bash
sudo systemctl enable nx-agent.service nx-voice.service
# 取消语音开机启动（不立即停止正在运行的服务）
sudo systemctl disable nx-voice.service
```

## 2.1 短期聊天记忆

露卡语音聊天和 8503 网页文字框共用当前会话记忆：最多最近 6 轮，同时限制总文本为 1800 字符，较长对话可能不足 6 轮。10 分钟没有成功聊天后，下次提问会清空旧记录；重启 nx-agent 或小车也会清空，不写入长期存储。8092 独立聊天页面不使用这份记忆。

每次仍需喊“露卡”或点手动唤醒。可先说“这次聊天记住，小车的小名是蓝豆”，再唤醒后问“我刚才起了什么小名”。清空时说“清空聊天记忆”“清除聊天记忆”或“忘掉刚才的对话”；也可在 8503 文字框输入。清空不删除系统日志，且不会影响导航。

记忆只用于聊天回答，导航仍要求完整明确的目的地命令，不会根据聊天历史推断并驱动车轮。

## 3. 音量调整

### 语音断句优化与测试（2026-09-11）

现已使用 CPU 上的 Silero VAD 判断人声，连续约 0.5 秒静音后提交 SenseVoice。唤醒后 10 秒仍没有完整语句则提示重说，不把超时截断的片段提交为运动指令。

8503 页面提供“测试语音识别（不执行动作）”：点击后等“在呢”，说一句话，露卡只回读识别结果，本次不会发送导航或聊天任务。仅测试模式将该段音频保存到 `/home/sunrise/luka_ws/e2e/voice_tests/`，用于与实际说法对照；普通对话没有新增录音保存。一次测试结束后退出测试模式，下一次普通唤醒仍按正常功能工作。

房间同音字纠错仅处理明确完整命令中的少量词：厨坊→厨房、卧市/卧事→卧室、浴市/浴是→浴室；不删除否定词，不对混合目的地或整句话做模糊匹配。识别准确率仍需以真人现场测试为准。

此次声音小的原因：USB 扬声器 PCM 音量为 46%（-20 dB）。已调至约 76%（-9 dB）。以下百分比按声卡档位取整。

```bash
amixer -c Device sget PCM               # 查看当前音量
amixer -c Device sset PCM 75% unmute     # 日常音量
amixer -c Device sset PCM 85% unmute     # 更响一些
amixer -c Device sset PCM 60% unmute     # 调低
nx-voice wake                           # 试听“在呢”
sudo alsactl store                     # 保存当前声卡设置
```

音频设备使用稳定名称：麦克风 `plughw:CARD=XFMDPV0018,DEV=0`，扬声器 `plughw:CARD=Device,DEV=0`。更换 USB 音频设备后需相应修改 `/etc/systemd/system/nx-voice.service`，执行 `sudo systemctl daemon-reload`，再 `nx-voice restart`。

| patrol_start | 开始巡航 / 巡航一圈 | 仅解析 |
| patrol_stop | 停止巡航 | 仅解析 |

普通聊天示例：“你好”“介绍一下你自己”“用一句话解释什么是激光雷达”。聊天由本地 Qwen 模型回答；首次请求需要加载，较热启动慢。

## 5. 实体手柄

| 操作 | 作用 |
|---|---|
| 手柄接收器插入 NX，摇杆居中，先松开 LB | 完成启动前的释放检查 |
| 按住 LB + 左摇杆前后 | 前进、后退 |
| 按住 LB + 左摇杆左右 | 左右平移 |
| 按住 LB + 右摇杆左右 | 左右自转 |
| 松开 LB | 停止手动运动 |
| 导航期间按住 LB，摇杆保持居中 | 取消导航并接管停车 |

当前手柄五挡前进限速为 0.4、0.5、0.6、0.7、0.8 米/秒，服务启动默认第 1 挡（0.4 米/秒）。导航前进上限保持 0.4 米/秒。松开 LB 后，按 X 降一挡、Y 升一挡；每按一次只调一挡，按住不连续改变。按住 LB 时调速键无效，避免行驶中突然加速。平移和自转随挡位同比缩放；自转指令上限已提高，五挡分别为 0.8、1.0、1.2、1.4、1.6 弧度/秒；底盘仍应用原有 0.7 转向系数，实际转速需实车测量。左右转向方向保持原设置。RB 不额外加速。重启手柄服务恢复第 1 挡。调速回执可用 `journalctl -u nx-gamepad -f` 查看。LB 取消导航后，松开不会自动恢复原目标，需要重新点航点。

## 6. 四楼导航

1. 打开 8503 页面，检查四楼地图上小车位置和朝向是否正确。
2. 在航点列表选择“厨房”“卧室”或“浴室”，点击“前往”并按页面提示确认。
3. 观察状态；停止时点击“停止导航”。手柄 LB 也可以接管。

| 航点 ID | 名称 | 说明 |
|---|---|---|
| wp_008 | 厨房 | 实际四楼航点 |
| wp_009 | 卧室 | 实际四楼航点 |
| wp_010 | 浴室 | 实际四楼航点 |
| wp_007 | home（充电点） | 保存的位置；不代表自动充电已实现 |

| wp_005 | wp_005 | 未明确命名，不建议日常使用 |

当前导航前进最高配置 0.4 米/秒；规划、转弯、避障会降低速度。地图可浏览多个楼层，但实际导航仅开放四楼。

## 7. 相机、录像和找东西

打开 8091/view，查看实时画面，选择 LocateAnything，输入要识别的物体，例如“冰箱”“柜子”“杯子”。返回的是模型候选框，需要看图确认。

录像查找：在“巡航录像与查找”区域开始录像→通过手柄移动小车或移动相机采集画面→停止录像→检查选中的录像→输入物体名称搜索→查看命中的时间点和截图。不需要为同一个物体重复录像。

没有结果时检查：是否选中了新录像、物体是否清晰出现在画面、名称是否过于具体。模糊、遮挡和候选帧抽样都可能造成漏检。当前查找不是地图上的精确物体定位。

聊天模型约 60 秒闲置后卸载，视觉模型约 30 秒闲置后卸载。相机页面服务与模型驻留不是同一件事；卸载模型后仍可保留画面。重推理与行驶并发尚未完整验证，也还没有完成自动切换导航/大模型的调度器。

```bash
# 手动卸载视觉推理模型，保留相机页面
curl -X POST http://127.0.0.1:8091/model/unload
# 关闭/开启聊天模型服务
sudo systemctl stop qwen-chat.service
sudo systemctl start qwen-chat.service
# 关闭/开启整个相机识别页面服务（停止会影响录像，先结束录像）
sudo systemctl stop locateanything-preview.service
sudo systemctl start locateanything-preview.service
```

## 8. 服务与维护命令

| 服务名 | 功能 |
|---|---|
| nx-robot.target | 小车核心服务启动集合，已设置开机启动 |
| nx-sensors | 上下雷达、IMU |
| nx-localization | 四楼地图、AMCL 定位 |
| nx-manual-base | 唯一底盘串口控制、里程计、导航开关 |
| nx-gamepad | 实体手柄输入 |
| nx-navigation | Nav2 规划、控制和防碰撞链路 |
| nx-dashboard | 8503 网页 |
| nx-agent | 本地语言代理，目前只解析动作 |
| nx-voice | 唤醒、听写、语音播报 |
| qwen-chat | 8092 聊天模型 |
| locateanything-preview | 8091 相机和视觉模型 |

```bash
# 启动核心服务，不会自动下发导航目标
sudo systemctl start nx-sensors nx-localization nx-manual-base nx-gamepad nx-navigation nx-dashboard

# 手柄相关服务
sudo systemctl start nx-manual-base nx-gamepad

# 停止导航服务，保留手柄能力；重新开启后仍需选择目标
sudo systemctl stop nx-navigation
sudo systemctl start nx-navigation

# 停止底盘服务，也会影响导航；恢复后检查定位再使用
sudo systemctl stop nx-manual-base
sudo systemctl start nx-manual-base nx-navigation

# 查看服务（按 q 退出分页，或保留 --no-pager）
systemctl status nx-voice nx-agent nx-navigation nx-manual-base --no-pager
systemctl --failed --no-pager
journalctl -u nx-navigation -n 80 --no-pager
journalctl -u nx-agent -n 50 --no-pager
journalctl -u nx-voice -f

# 资源和音频设备检查
free -h
df -h /
tegrastats               # Ctrl+C 停止查看
arecord -l
aplay -l
amixer -c Device sget PCM
```

重启或关机前先停止导航、结束录像、确认车辆停稳：

```bash
sudo systemctl stop nx-navigation nx-manual-base
sudo reboot              # 重启；重新定位后再导航
# 或者：sudo poweroff    # 关机
```

## 9. 常见故障

| 现象 | 处理 |
|---|---|
| 喊“露卡”没反应 | `nx-voice status`；未运行就 `nx-voice start`；等约 35 秒后用 `nx-voice wake` 排除唤醒词问题 |
| 有“在呢”，但听不清 | 用第 3 节调扬声器 PCM 音量 |
| 有“在呢”，但不回答 | 等提示结束再说；查语音日志是否有 `command_sent`；检查 nx-agent、qwen-chat 服务 |
| 网页手动唤醒提示未就绪 | 在 SSH 启动语音服务，等待加载完成后重试 |
| 说“去浴室”不移动 | 确认先唤醒，再单独说“去浴室”；检查网页状态、定位和导航服务。网页文字框仍只解析 |
| 网页打不开 | 确认同一局域网、NX 地址没变，并检查对应服务 |
| 画面不显示 | 检查相机 USB 和 locateanything-preview 服务 |
| 导航不走/中途停 | 看网页状态和导航日志；检查定位、双雷达、底盘服务及 LB 是否按下，不要用关闭防碰撞来绕过问题 |
| 重启后位置不对 | 先重新定位，暂不下发目标 |

本说明列出当前部署版本的日常入口、语言代理全部功能类别和维护命令；尚未开放的功能不能仅凭自然语言回执判断已经执行。

## 10. 语音回答加速（2026-09-11）

已启用聊天分句输出、语音短语分段和后台预合成，无需额外开关。播放当前片段时准备后续音频，保留原有音色和短期聊天记忆。直接喊“露卡”，等“在呢”后说话即可。

同一测试文本的首次音频准备时间约从 2.95 秒降到 2.67 秒；两句话之间原有约 3.4 秒的合成等待被后台预合成覆盖。仍有正常标点停顿，首次出声也仍需等待大模型和语音合成。长句切分的自然度可通过实际听感继续调整。

诊断日志：`journalctl -u nx-voice -f`，可查看 `tts_pipeline_ready`、`tts_play_start`、`tts_segment_done`。语音服务重启后需要约 30 秒加载与准备缓存。

## 11. 语音巡航录像与找东西

先核对四楼定位和雷达与墙体是否重合。每条指令先喊“露卡”，等“在呢”再说：

- “开始巡航录像”或“开始巡航”：小车会行驶，按厨房 → 卧室 → 浴室走一遍。先确认录像打开，再导航；每站到达后停留 4 秒继续录像。
- “停止巡航”：取消当前任务、关闭导航并保存已录内容。手柄 LB 接管、导航取消/失败也会结束巡航，不继续下一站。
- “帮我找冰箱”“帮我找杯子”“查找手机”：若正在巡航，先停止并收尾录像，然后从新到旧搜索已保存录像，首个有候选的录像检索完成后返回结果。若正在收尾或另有搜索，请稍后再试。
- “停止查找”：取消搜索。普通“停止”“停车”也会停止当前巡航或查找，并关闭导航。
- “沙发在哪里”“告诉我沙发的位置”“沙发找到了吗”：直接查询保存的找物结果，不通过聊天模型猜测。“找到了吗”查询最近搜索的物品。

首次检出候选画面即主动语音通知，不必等待整段录像搜索结束。语音队列忙时会重试，同一搜索只主动通知一次；主动追问可以再次播报。播报中的地图坐标属于当时的小车观察位置，不代表物体精确坐标。

8503 页面新增“语音巡航录像与找物”，显示任务进度、候选截图、录像时间和观察位置。8091/view 仍可查看完整录像与搜索历史。新录像每两秒保存关键帧和相机时间对应的地图变换；观察位置是当时小车所在位置，不是物体的精确坐标。旧录像无位置记录时会明确显示缺失。

巡航只覆盖沿途相机实际看到的画面，不自动环视；两秒采样可能漏掉短暂出现或遮挡的物体。视觉结果是候选，需看框确认。查找结果不会自动驱动车辆前往物体，需要明确说“带我去”或点击带路按钮。服务重启不自动续航，恢复时尝试关闭导航和保存所属录像。

### 找到后带我去

找到带有效位置的候选时，露卡会问是否带你去观察位置。重新喊“露卡”，等回应后说“带我去”或“带我过去”。默认使用最后通知或追问的找物结果；想去沙发的观察位置，可以先问“告诉我沙发的位置”，然后再唤醒说“带我去”。前端也可点击“带我去观察位置”，按钮旁显示物品名称。

小车会导航回录像中看见物品时的底盘位置，并恢复当时朝向。到达后停车重新识别，分别播报再次发现候选或这次没有看见。没有同楼层位置记录的录像不能带路；观察位置不等于物体本身坐标。可说“停止”“取消带路”或按手柄 LB 取消。若查找仍在运行，会先尝试结束查找；若识别还在收尾，等待后再下达带路指令。

本功能已完成目标校验、到达/失败分支模拟和部署接口验证，尚未进行实车带路及到达重识别联调。
