# P6 Official following + Luka safety chain

## Motion graph

Nav2 goals generated by `tros_person_following` continue through the existing
Luka Nav2 velocity pipeline.

The official following node also has a direct `cmd_vel_topic` used for
edge-turn/search/stop commands. In real mode this is now deliberately injected
at `/nx/nav_smoothed`, not `/cmd_vel`:

```text
tros_person_following direct turn/stop
              |
              v
      /nx/nav_smoothed
              |
              v
        heading guard
              |
              v
       /nx/nav_guarded
              |
              v
      collision monitor
              |
              v
         /nx/nav_safe
              |
              v
       ddsm_car_control
```

This preserves the existing product safety chain.

## Explicit follow parameters

- follow_distance_min: 1.8 m
- follow_distance_max: 2.0 m
- follow_hysteresis: 0.1 m
- follow_min_safe_distance: 0.5 m
- follow_goal_pub_rate: 2.5 Hz
- follow_goal_dist_deadzone: 0.3 m
- follow_goal_yaw_deadzone: 0.6 rad
- tracking_to_lost_timeout_sec: 1.0 s
- lost_to_idle_timeout_sec: 5.0 s
- idle_search_total_timeout_sec: 0.0 s

## Dry-run boundary

The launch default remains `dry_run:=true`:
- action: `/luka_follow_dryrun/navigate_to_pose`
- direct velocity: `/luka_follow_dryrun/cmd_vel`

No physical S100 ROS shell is available in this GitHub execution environment,
so the ROS integration dry-run must be executed on the board before P10. The
static contract test protects the endpoint mapping in CI/review.
